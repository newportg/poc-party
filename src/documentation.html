OVERVIEW

One reusable record for each Party

The POC explores how a person, company, or group can have a stable identity that can be referenced in different matters. It is a static browser app: the main catalogue works without a backend, build step, or account.

Implementation files index.html and app.js provide the interface, party.js contains the domain rules and fixtures, and config.js controls the optional API URL.
PARTY MODEL

Identity and relationships

Every record has a stable demo ID, a type, a display name, a status, and illustrative timestamps. Type-specific fields describe individuals and companies. Groups are Parties too; their members are represented by separate membership links.

  • Party type is fixed when a record is created.
  • Groups can contain individuals and companies, but not other groups.
  • Membership dates and Active/Ended status preserve a simple relationship history.
  • A group needs at least one active member to be referenced in a matter.
  • Matter roles describe that Party's role in that matter; they do not change its identity.
USING THE APP

Find, view, and edit records

  1. Use the catalogue search to find a Party by its ID or name, member details, or matter reference. Narrow results with the type and status filters.
  2. Select a row to view its identity, group membership, and matter references in the detail panel.
  3. Choose New Party to add a record or Edit record to change one. An existing Party's type cannot be changed.
  4. For groups, add or end memberships and supply dates and optional group-specific roles. Ended memberships remain as history.
  5. Changes are saved in this browser. Use Reset sample data on the app to restore the fictional starting records and discard local edits.

The detail pane zoom controls adjust only that pane. The app also remembers the selected light/dark theme in this browser.

COMPANY LOOKUP

Search the Companies House register

When creating or editing a Company, the lookup can search by name. The exact query Zoomalong Limited uses built-in mock response data and needs no network or API key. Other queries use the live public search service.

In the configured proxy flow, the browser sends the key in the X-Companies-House-Api-Key request header; the proxy forwards it to Companies House using Basic authentication. Selecting a result can populate the company name, registration number, legal form, jurisdiction, and mapped status.

The key is not saved by the app and is cleared when the form closes. It is still visible to the user and sent from the browser, so it cannot be treated as a protected secret in this static app. Search responses are for demonstration and are not legal verification.

IMPLEMENTATION

Files, service endpoints, and local checks

  • src/index.html and src/documentation.html are the app and this guide; both are published as static pages.
  • src/app.js handles display, forms, and browser storage; src/party.js contains sample data, domain validation, and search helpers.
  • api/main.py implements the optional FastAPI proxy. The service provides /health, /heartbeat, and /api/companies/search; interactive API documentation is available at /docs.
  • The proxy accepts a company-name query and the caller's API key, then requests up to 10 results from Companies House. It does not store the key.

For local development, install Podman Desktop and Node.js, then run .\scripts\run-local.ps1 from PowerShell in the repository. This builds and starts the API container and serves a temporary client copy configured for the local API.

Run the focused client tests with node --test tests/party.test.cjs. API tests are run from api/ with python -m unittest -v.

DATA AND LIMITATIONS

What this POC does not provide

Party records are stored in the browser's localStorage under poc-party.records.v1. They are not encrypted, backed up, or shared with other browsers. A person using this browser can inspect and edit that storage.

  • No sign-in, authentication, or access control
  • No production database, server-side record validation, or audit trail
  • No retention enforcement, identity matching, merge workflow, screening, or compliance process
  • Timestamps are illustrative client-side metadata, not attributable audit events
  • Companies House results are not independently verified by the app

Use fictional demonstration data only. Do not use shared or public computers to enter API keys.

API CONTRACT

Companies House proxy API

The optional FastAPI service proxies company searches to Companies House. The default local base URL is http://127.0.0.1:8000. The downloadable api-contract.md contains this contract in Markdown.

Service endpoints

  • GET / returns the service name and /docs link.
  • GET /health returns {"status":"ok"}.
  • GET /heartbeat returns {"status":"awake"} and can wake a sleeping hosted service.
  • GET /docs provides interactive FastAPI documentation; GET /openapi.json provides the schema.

GET /api/companies/search

Required request headers:

Accept: application/json
X-Companies-House-Api-Key: <caller Companies House API key>

The required q query parameter is a company name with 1-160 characters after trimming.

GET /api/companies/search?q=ACME%20LTD
X-Companies-House-Api-Key: caller-key

The proxy forwards the request to Companies House with items_per_page=10 and Basic authentication using the caller's key as the username and an empty password. It does not persist or expose the key.

Successful responses contain the Companies House result items and optional pagination fields:

{
  "items": [
    {
      "title": "ACME LTD",
      "company_number": "01234567",
      "company_status": "active"
    }
  ],
  "total_results": 1,
  "items_per_page": 10,
  "start_index": 0
}

Errors and direct lookup

Invalid or missing query and header values return 422. Other proxy errors are:

  • 401 — Companies House rejected the API key.
  • 502 — upstream network failure, invalid JSON, or unexpected response.
  • 504 — upstream request timed out.

Error bodies use {"detail":"A human-readable message"}; messages must not echo the API key. When no proxy URL is configured, the browser can call Companies House directly. The case-insensitive zoomalong limited query uses a local mock without a network request or API key. Other direct requests require an API key and distinguish network failures, rejected credentials, and rate limits.

Data and storage

Store the editable catalogue under poc-party.records.v1 in browser localStorage. Store the theme under poc-party.theme.v1. The reset action restores the fictional sample records.

Every Party has a stable ID, type, status, display name, timestamps, memberships, and matter participations. Types are Individual, Company, and Group. Individuals have person fields; companies have legal and registration fields; groups have effective-dated membership links.

Groups may contain only individuals or companies, not groups. Memberships retain Active and Ended history. Matter participation is contextual and stores matter ID, matter name, and role on the Party record.

UI behavior

  • Searchable Party catalogue.
  • Type and status filters.
  • Selected Party detail panel.
  • Create/edit Party dialog.
  • Membership and matter-reference sections.
  • Company lookup panel.
  • Detail-pane zoom from 80% to 140%.
  • Light/dark theme toggle.
  • Reset sample-data action.

Search covers Party ID, display/name fields, member ID/name/role, and matter references. Selecting a catalogue entry updates the detail panel. Company search results can populate company name, registration, legal form, jurisdiction, status, and dissolution data.

The built-in case-insensitive query zoomalong limited returns the mock Companies House response without a network request or API key.

Company search and API

When window.PARTY_API_BASE_URL is configured, request:

GET /api/companies/search?q=<company name>
X-Companies-House-Api-Key: <caller key>

The proxy forwards the key to Companies House using Basic authentication and does not persist it. It exposes /, /health, /heartbeat, /api/companies/search, /docs, and /openapi.json.

The browser also supports direct Companies House lookup when no proxy URL is configured. Invalid keys, rate limits, and network/access failures must be reported distinctly.

Validation and tests

Validate required display name, type, status, unique IDs, individual names, membership target types, membership date ordering, duplicate active members, self-membership, matter reference IDs, roles, and active-member requirements for participating groups.

node --test tests/party.test.cjs
cd api
python -m unittest -v

Limitations

There is no authentication, authorization, production database, audit trail, retention enforcement, identity matching, screening, compliance workflow, or secure client secret storage. All records are fictional demo data. Do not enter real personal or confidential information.
